# 待用户确认：统一 A–D 两阶段生成方案

状态：**仅方案，未实施、未运行、未改变预算**。来源：三轮真实 Research 均在一次结构修复后仍未满足正文/证据逐字对齐；不是超时或 Ollama 解码失败。提示词强化和字段改名尚未解决问题，不能据此断言 Granite 对所有任务都无能力。

建议下一次调整共享生成流程，将模型同时写正文、完整声明元数据和长来源摘录的任务拆开：

1. 先生成该逻辑单元的正文与必需分析/财务内容，保存为内部草稿。草稿不算完成计划书，也不通过原完整契约门。
2. 固定草稿正文，再生成对应声明、评分、财务引用与证据选择。让模型从正文与冻结证据中的精确片段选择引用，用可验证的片段 ID/位置表达；确定性组装只复制被选中的原始文字，不生成或改写正文、来源或财务值。
3. 最后按原 canonical 字段组装并执行原完整 schema、来源、逐字锚、财务和 lineage 校验。无关证据仍不应被当作支持；人工 Gold 与六维评分继续独立，不把确定性匹配当作语义正确。

全部 A–D 同时采用相同两阶段方式；保留四批写作和既有业务角色/路由。原“一次结构修复”在同一逻辑单元的两个阶段之间共享，不能变成每阶段各一次。Critic 仍按现有单阶段规则；条件 Revision 数量不增加，但被修订生成单元同样分两阶段。
